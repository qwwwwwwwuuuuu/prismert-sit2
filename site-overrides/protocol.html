PUSHIN reference model · The terminal uses generated data and virtual collateral. On-chain settlement is not deployed.

System architecture

Four stages from venue data to settled position. The index is calculated off-chain; the limits on it, the payout cap and signature checks are applied by the contracts. The contracts haven’t undergone an audit and deployed only on Robinhood Chain Testnet.

Architecture notes

Pipeline

Each component is marked with what is available now, not with what is planned.

  1. 1

    Ingestion

    Venue reads, each 15 seconds. Each source reports its own latency and health.

    • Deribit option surface — BTC and ETH, all listed expiries, one request each
      Live
    • Binance funding — premiumIndex, 8h interval
      Live
    • Hyperliquid funding — metaAndAssetCtxs, 1h interval
      Live
    • Lighter funding — the native leg: Robinhood Chain perps, unit-checked against Hyperliquid each round
      Live
    • Derive option surface — second options venue for the index
      Planned
  2. 2

    Analysis

    The index is calculated off-chain; the limits on it are applied on-chain.

    • C-VIX index engine — variance replication, 30-day constant maturity · core/cvix.ts
      Live
    • Oracle dampener — ±20% per block, 5% step on a distrusted push · CVIXOracleDampener.sol
      Built
    • Dynamic skew engine — quadratic borrow rate with a depth floor · DynamicSkewEngine.sol — charged through a borrow index
      Built
    • FR-BASIS accrual — size × ΔFR × Δt ÷ 28800 into a carry index · PUSHINSettlement.sol; per round on the paper venue
      Built
  3. 3

    Execution

    Signed intents are validated and queued off-chain, then settled in batches.

    • Session keys — a single wallet signature delegates a scoped, expiring key; orders then sign in the browser · /api/session
      Live
    • Intent intake — EIP-712 verification, delegation, nonce, deadline, size, leverage and balance checks · /api/orders
      Live
    • Matcher — re-verifies, enforces limit price, fills at the index against the pool
      Live
    • Simulated settlement — positions, fees, capped PnL and a ledger under the contract's rules, on test collateral
      Live
    • PUSHINSettlement — on-chain signature and session checks, batch settlement, each order on its own
      Built
    • Relayer → settleBatch — submitting matched intents on-chain
      Built
  4. 4

    Settlement

    Collateral, the payout pool and liquidation.

    • PUSHINVault — USDG at 6 decimals; pool-only escrow of the 8× cap at open
      Built
    • LiquidationModule — capped PnL, maintenance threshold at 90% of margin
      Built
    • Liquidation keeper — liquidates past 90% with costs counted — paper ledger, or liquidate() on-chain for a bounty
      Live
    • Indexer — positions, balances, ledger and open interest from settlement, vault and oracle events
      Built
